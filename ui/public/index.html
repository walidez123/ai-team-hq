Field guide

Every element on this console, what it's for, and how to work the crew.

1

Masthead — status, clock, crew setup, guide

Top-right. line clear means nobody is working; crew working (n) means n runs in flight. The gear opens Crew setup — assign a model to each employee (saved to their agent files; applies next dispatch). The ? reopens this guide any time. Esc closes all three.

2

The line rail

The six stations a task passes through: intake, plan, build, test, review, report. Stations glow terracotta while a run is live and stamp sage when it's done — with an elapsed timer on the right edge. Click any station to open its drill-down: who owns it, their model, and what landed in the shift log there.

3

Console vitals

One honest line: how many runs the team has filed, what percentage ended green, average run time, and how the last one went. It's journaled in reports/.metrics.jsonl — nothing hidden, nothing averaged over.

4

The crew — left column

Each employee is a stamped badge: code (PM project manager, AR architect, BE backend, FE frontend, QA tester, RV reviewer, RP reporter, EX explainer), their duty, their free model, and a punched hole + barcode with their number. A circle beside the status means standby; orange means on shift. Click anyone to assign them work directly.

5

Who takes this task

Dropdown in the Live wire header. dispatcher — full pipeline runs brief → plan → build → test → review → report by itself. Or pick one employee for focused work — e.g. @qa to just re-run the suite.

6

Known projects & New project…

Type any folder path in project folder and hit Register folder — it joins the dropdown permanently. New project… scaffolds a git repo with team files (or adopts an existing folder, only adding what's missing). The HQ works in any directory on this PC.

7

Assign a task

Type in the big field and hit Assign task (or Ctrl/Cmd + Enter). Be specific: what, where, acceptance criteria. The crew works from what you write — vague brief, mediocre work.

8

The live wire

Every dispatch streams here. Muted italics = system, [tool] … = a tool call, green ✓ = done, coral ✗ = failed, and a blinking ▌ when the wire is idle. Scroll is automatic.

9

Stop run

Halts the current run at the next safe point. Two agents edit the same folder? Stop one — branches are cheap, corrupted merges aren't.

10

Filed reports & the ledger

@reporter writes every finished task to reports/. Pick a slip on the right to read it in the ledger view — the sage FILED stamp means it made it to record. Reports never lie: skipped steps and waived findings must appear at the top.

11

Keyboard

/ jump to the task field · Ctrl/Cmd + Enter assign · ? open/close this guide · Esc close it. Standard Tab/Shift+Tab navigation everywhere; focus rings are terracotta.

12

Working agreement

One task = one branch (task/<slug>) = one report · small commits · you merge, always · never paste secrets (free models may train on inputs) · reviewers block on CRITICAL findings · if blocked, the crew stops and tells you rather than shipping partials.

This guide opens once, then lives behind the ? button — top-right, always.
